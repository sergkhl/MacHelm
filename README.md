# MacHelm

A macOS utility that brings cursor hiding, fan control, power settings, process activity, developer storage cleanup, and personal startup services into one window and the menu bar.

**Version 0.1 · build 1.** This is a source release for macOS 26 or later. Build it with Xcode 26 or later. A signed, notarized application download is not included in this release.

## Tools

| Tool | What it does |
| --- | --- |
| **Cursor hide** | Hides the system pointer with **Ctrl+Option+Command+H** (`⌃⌥⌘H`), including while another app is active, and hides it again if macOS shows it before you restore it. This experimental feature uses private WindowServer APIs; see [behavior and compatibility](docs/cursor-hide.md). |
| **Fan Control** | Uses a temperature ramp with CPU, GPU, and thermal-pressure protection. A signed helper controls the fans and tracks ownership and recovery. See [behavior and hardware limits](docs/fan-control.md). |
| **Power** | Keep Awake, Sleep Now, and the macOS display and system sleep timers. Keep Awake can pause at a chosen battery level; the helper adds control over lid sleep and the system timers. |
| **Activity** | Shows the five heaviest process groups for CPU, memory, GPU, energy, and disk over a selected time window. Expand a row to inspect its processes, quit an app, or open Activity Monitor. |
| **Storage** | Scans developer caches, simulators, runtimes, and Android emulators, as well as app caches, leftover update downloads, idle Codex chats and Claude Code sessions, merged or idle worktrees, device backups, and the Trash. Review the measured targets and confirm a cleanup; what cannot be restored starts unchecked. The [Python cleanup utility](Storage/README.md) also works in a terminal. |
| **Startup Services** | Imports your LaunchAgents or adds programs and scripts. Manage their login behavior and current-session state while keeping each service's launchd rules. See [Startup Services](docs/startup-services.md). |

The dashboard opens on Overview, with detailed pages in the sidebar. Closing the window leaves MacHelm running in the menu bar. Settings (`⌘,`) controls opening at login, the temperature/fan readout, and Activity's reading pace.

On normal Quit, MacHelm attempts to restore its own cursor hide request, asks Fan Control to return its fans to automatic, and releases Keep Awake. Managed startup services continue running, and the macOS sleep timers retain their values.

## Build

Open `MacHelm.xcodeproj`, select the **MacHelm** scheme, and choose your Apple development team for the app and its embedded targets: **FanControlHelper**, **ToolkitHelper**, and **MacHelmServiceRunner**. Use the same team for all four products.

A command-line build can choose that team explicitly:

```sh
xcodebuild -project MacHelm.xcodeproj -scheme MacHelm \
  -configuration Debug -derivedDataPath build/xcode \
  DEVELOPMENT_TEAM=YOURTEAMID CODE_SIGN_IDENTITY="Apple Development" build
```

The result is `build/xcode/Build/Products/Debug/MacHelm.app`. The helpers require a real Apple signing identity and matching team; an unsigned or ad-hoc build does not enable privileged features. Building an app does not install or approve its helpers.

The checked-in Xcode project, scheme, workspace, and bundle metadata are generated by `scripts/generate-xcode-project.py`. Contributors can regenerate them after changing source membership or build settings; see [the development workflow](CONTRIBUTING.md#development).

For Startup Services actions, place your signed build at `/Applications/MacHelm.app` and approve background items when macOS requests it. Service definitions reference the runner inside that application; see the [removal instructions](docs/startup-services.md#removing-or-moving-machelm) before moving it.

MacHelm uses the fresh `io.github.sergkhl.MacHelm` namespace for preferences, helpers, and app-owned data. Version 0.1 starts with fresh settings and has no automatic migration from earlier private installations.

## Test and inspect

Check the generated project and run the Swift package and cleanup utility tests:

```sh
python3 scripts/generate-xcode-project.py --check
swift test --scratch-path build/swift-tests
python3 -B -m unittest discover -s Storage -p 'test_cleanup_macos_dev.py'
```

These verify generated-file consistency and code/fixture behavior; passing them does not establish visible cursor behavior in a game, native fan recovery, background-item approval, or behavior on another Mac. Artifact checks inspect a signed build without registering its services:

```sh
./scripts/verify-fan-artifact.sh build/xcode/Build/Products/Debug/MacHelm.app
./scripts/verify-toolkit-artifact.sh build/xcode/Build/Products/Debug/MacHelm.app
```

The cursor's “Hide requested” state records the owner's request. While it stands, MacHelm checks ten times a second whether macOS shows the system pointer and hides it again. It cannot hide the pointer while WindowServer gives the Dock control, and games may draw their own pointers. The [cursor documentation](docs/cursor-hide.md) explains these limits and normal-Quit cleanup.

Fan hardware access is restricted to the M2-family sensor map in the source and requires usable fans and sensor readings. Earlier development observations on one M2 Pro are limited historical evidence, not qualification of the renamed 0.1 artifact or all models in that map. Cursor hiding, Activity's GPU and power readings, and the lid-sleep feature use private or undocumented macOS interfaces and may be unavailable on other systems. The app is not sandboxed. Storage requires Python 3 and the relevant developer tools installed locally. Measuring device backups and the Trash needs Full Disk Access, which the Storage page helps you grant, and emptying the Trash asks once for permission to control Finder.
